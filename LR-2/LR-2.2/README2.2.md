# Лабораторная работа 2.2: Сумма двух — тесты для функции `add(nums, target)`

Тесты лежат в файле `test_add.py`. Запуск осуществляется командой:
`python -m unittest -v test_add.py`

Функция может вернуть индексы в любом порядке и любую подходящую пару, поэтому в тестах перечислены все допустимые ответы.

## Группы ситуаций

1. **Базовые случаи (Happy path):** Проверка стандартного сценария, когда пара чисел находится в середине списка. Подтверждает, что функция в принципе работает.
2. **Граничные случаи:** Проверка, когда одно число стоит в самом начале (индекс 0), а другое в самом конце. Часто в циклах допускаются ошибки на последнем элементе.
3. **Сложные структуры данных:**
   * **Одинаковые числа (дубликаты):** Проверка, что один и тот же элемент не берется дважды.
   * **Нули:** Проверка корректной работы с нулями.
   * **Отрицательные числа:** Проверка, что алгоритм не рассчитан только на положительные числа.
4. **Негативные случаи (отсутствие ответа):** Пары вообще нет в списке; список пустой; в списке только один элемент.
5. **Побочные эффекты:** Проверка того, что исходный список не изменяется (функция не должна его сортировать или модифицировать).

## Ошибки, которые ловят тесты

| Тест | Какую ошибку может найти |
| :--- | :--- |
| `test_basic_scenario` | Функция вообще не работает или возвращает не те индексы |
| `test_pair_at_boundaries` | Ошибка в границах цикла: последний элемент не проверяется |
| `test_no_solution` | Вместо `None` возвращается что-то другое (`[]`, `False`) или происходит ошибка |
| `test_empty_list` | Ошибка при передаче пустого списка |
| `test_one_element_list` | Элемент складывается сам с собой, хотя пары нет |
| `test_same_elements_not_reused` | Один элемент берется два раза (например, `[3, 3]` для target=6 в списке `[3]`) |
| `test_negative_numbers` | Функция рассчитана только на положительные числа |
| `test_zeros_and_duplicates` | Нули пропускаются или одинаковые числа теряются |
| `test_original_list_unchanged` | Функция сортирует или изменяет переданный список |

## Разнообразный набор

Каждый тест проверяет свою ситуацию, а не повторяет одно и то же с другими числами: обычные случаи, границы, отсутствие ответа и неизменность входных данных. Это позволяет отловить большинство логических ошибок в реализации функции.
